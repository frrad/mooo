# Ordinary file (18)

Research date: 2026-10-08. Authorized sources: Android KakaoTalk 26.8.2 APK and
owned A/B emulators. No public protocol implementation was consulted.

## Observed wire and sender contract

A opened File → Select from File in the owned B chat and selected one generated
48-byte TXT document. Selection immediately submitted a type-18 message: there
was no later Send confirmation. B’s raw MSG attachment carried `k`, `url`, `cs`,
`name`, `s`, `size`, `expire`. Independent HTTPS download returned the exact
original generated bytes and matched SHA-1 `cs`. Expiry used milliseconds, unlike
ordinary video’s seconds. The synthetic fixture preserves both size fields and
owned generated content/checksum, replacing token, URL and expiry.

Android FileChatLog initializes a nested FileAttachment from attachment JSON,
reading name, s and expire; the observed extra size field is not its size getter.
FileAttachment compares expiry against System.currentTimeMillis and regards
values at/before its historical validity threshold as invalid. Local-file paths
must exist and match declared size; invalid local_path state is cleared and
persisted. Relay resource/token selection, cancellation, partial-download status,
thumbnail generation and cleanup are separate paths. These are static leads;
full uploader/downloader callback and all persistence/consumer parity are gaps.

## Implementation-neutral bridge contract

Accept the observed type-18 direct URL form with bounded UTF-8 basename, token,
positive byte size, SHA-1 and positive millisecond expiry. Preserve received bytes
and filename as native m.file; derive MIME from bounded content sniffing rather
than trusting an absent wire MIME. Use existing Matrix encryption. Validate
allowlisted HTTPS origins and redirect destinations, exact size and checksum,
and expiry before fetching. Deterministic expiry/invalid/checksum failures become
notices; transient fetch/upload failures leave delivery uncommitted.

mooo policy: 64 KiB attachment JSON, 64 MiB file, 512-byte filename/token;
reject duplicate JSON fields, path separators and filename control characters.
Resource-only, cloud/backup/restore paths and LargeFile (29) remain unsupported.
Outbound files from Matrix are covered in [group outbound media](bridge/GROUP-OUTBOUND-MEDIA.md). Actual Matrix application file-opening parity remains
unvalidated. Owned Android A/B acceptance passed for two distinct synthetic text files: one
catch-up delivery and one fresh live delivery. Both became encrypted native
`m.file` events; the Matrix SDK verified filenames, text/plain MIME, sizes and
exact decrypted SHA-256 hashes. The official receiver displayed both file cards.
A normal bridge restart retained exactly two unique file messages; the earlier
file remained decryptable with the retained Matrix device keys. A fresh later
text was submitted once. Exact committed-head acceptance remains pending.

## Guarded emulator submission

The helper starts in the explicitly selected owned chat. It verifies peer,
empty composer and the SHA-256 of a pushed synthetic file (up to 4 MiB) before
opening File → Select from File, selects only one exact synthetic filename under
its Android DocumentsUI item, and reserves an exclusive external attempt receipt
before that selection. After selection it requires the owned peer and newly
visible exact filename within four UI dumps. A filename already visible before
submission is rejected. A controlled binary attempt returned to chat without a
received file; its cause remains unresolved. Returning to chat alone previously
reported success; a failing-first regression now protects the stricter outcome
check. An uncertain outcome preserves the receipt and forbids automatic retry. Unknown providers/screens or ambiguous filenames stop.
